## Product scope and requirements

Before implementing or refactoring features, read:

1. `docs/PROJECT_SCOPE.md` — release scope, priorities, exclusions.
2. `docs/REQUIREMENTS.md` — functional and nonfunctional requirements with IDs and acceptance criteria.
3. `docs/ARCHITECTURE.md` — design decisions and module boundaries.
4. `docs/ROADMAP.md` — implementation sequence and release gates.

Treat P0 as release-blocking, P1 as optional, and P2 as deferred. Do not introduce P2 features or rewrite working modules without explicit approval. Cite requirement IDs in PR descriptions and commit summaries. Maintain small, reviewable commits and run lint, tests, and build before requesting merge.
